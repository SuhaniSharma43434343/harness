# Changelog

## 0.1.0 (unreleased)

- Intake: typed answers match an option by number, value, label (any case) or the start of a label, and an answer that fits no option or several is asked again at once. Before, typing "up to 12 pages" or "AAA" failed the whole round with SCHEMA_INVALID after the last question.
- The planner: `forge plan` (and every `forge run`) writes the task contracts for the phases whose work is the agents': research, page content (seeded from the site's draft pages) and the asset register, each with a `forge check` verify command. This is what gave the first real-model run its work. It ran on 2026-10-29 on the sample business site: research, content and the asset register on a small model, about $0.04 for the first two.
- Phase exits and the last commands: `forge advance` moves a project on only when the phase's tasks, evidence and approval are all there (refusals name what is missing), and `forge run --advance` keeps going until an approval or a blocker. `forge preview` (local, after a secret scan), `forge deploy --preview|--production` (vercel, with the form function and a smoke test), `forge report` (the final report from the ledger), `forge test --mock` and `forge demo` (the sample project to a local preview, no model or paid API). No command is listed as planned any more.
- T29: `forge audit` runs `npm audit` on the harness, starter and test-tool lockfiles and scans the package ZIP, workspace and logs for secrets, writing a dated report. Lighthouse in `tools/` moves from 12.8.2 to 13.5.0, which clears 29 advisories (10 high) in its dependencies. The first audit report is in `docs/audits/2026-10-29.md`.
- T12: approach modules APP-03 (Three.js scene behind a poster), APP-05 (GLSL background with a quality ladder, no package), APP-07 (the APP-02 + APP-03 (+ APP-05) composite with a shared budget and one WebGL canvas at a time) and APP-08 (scroll-scrubbed frame sequence and depth parallax, frame budget and provenance), each with build, fallback and budget tests. Every approach now has a module. The test-tool loader now works on Windows, so the browser tests run there.
- T25: operator docs: `QUICKSTART.md` (one project from brief to a gated, QA-reviewed site, written from a real end-to-end run), `docs/claude-code.md`, `docs/cursor.md`, `docs/troubleshooting.md`, and an overview of all eight approaches in `docs/approaches.md`; README docs index. Fixes found by the walkthrough: `buildSite` uses `npm ci` only when the lockfile matches `package.json` (`lockInSync`), the SEO gate accepts absolute sitemap URLs, and the dependency gate reports optional build-only binaries (such as sharp's LGPL builds) as a moderate licence note instead of a failure.
- T20: the APP-04 Spline module (`SplineScene`: the operator's scene behind a poster, loaded after LCP and the page, events wired both ways; poster fallback for a missing scene, no WebGL, reduced motion, low-end devices, slow networks and failed loads) and the APP-06 Game-Like module (`Game`: one bounded collect mechanic in Phaser with keyboard and pointer controls, progress, synthesised sound and skip, over an explainer that is the fallback). `siteReport` now separates up-front from on-demand JavaScript. Build, fallback and budget tests for both.
- T19: the APP-02 Cinematic Scroll module: `ScrollStory` and `Chapter` sections with GSAP, ScrollTrigger and Lenis loaded on demand, and a static stacked fallback with CSS reveals for reduced motion, low-end devices, slow networks and failed loads. Approach modules (`src/approaches/`), the shared `capability()` check in the starter, and `forge approach`. Build, fallback and budget tests; a real-device log template. See `docs/approaches.md` and `skills/app02/SKILL.md`.
- T24: the QA Verifier. `qaReview` runs the gates with fresh evidence per review and keeps `reports/defects.json` (new `defectReport` schema) and `reports/qa-log.md`; `runRepairLoop` hands open defects to the builder as repair tasks through the runner, re-reviews, and escalates after 3 loops. `forge qa [--repair]`. End-to-end tests on every seeded defect. See `docs/qa.md`.
- T22: the browser gates: routes, accessibility (axe-core at three widths and with reduced motion), forms (empty, success and failure submissions against an intercepted endpoint), responsive (six widths, with screenshots) and performance (Lighthouse median of three runs, plus the JavaScript budget). A static server for `site/dist`, Playwright, axe-core and Lighthouse adapters with plugin manifests in `src/plugins/`, and the tools pinned in `tools/package.json` (`scripts/setup.sh --with-test-tools`).
- T21: the content, claims, licence, secrets, SEO and dependency gates in `src/gates/`, with `runGate`, `runGates`, `qualityFloor` and `forge gates`. Every gate fails a site with no build or no text, passes the known-good fixture and catches its seeded defects. The starter now builds `sitemap.xml`, `robots.txt` and Organization JSON-LD. See `docs/gates.md`.
- T23: gate fixtures in `fixtures/sites/`: a blank site, a known-good site, and 21 seeded defects covering all 11 gates, with `materializeFixture` and fixture tests. Adds `node-html-parser` (MIT) for the gates.
- T17: design directions and rules. `proposeDirections` ranks an open-licensed font catalog, palette families and layouts against the brief's tone and returns 3 to 5 distinct directions; `checkDesignRules` checks licences, recomputed contrast, distinctness, the avoid list, motion and renders; `renderDirections` writes HTML specimens and desktop and mobile screenshots. `forge directions`. See `docs/design.md`.
- T18: starter website and APP-01 module. `starters/astro-base/` is a static Astro site styled only from design tokens, with pages from Markdown content and sections resolved from `src/sections/<approach>/`. `forge site` writes a project's brief, tokens (from `design/tokens.json` or the chosen direction, contrast-checked) and content into it; `--build` builds it and checks the 150 KB JavaScript budget. New `tokens` and `siteConfig` schemas, `docs/starter.md`, `skills/app01/`, and build tests for all 7 sample briefs.
- T11: `forge package` builds `forge-v<version>.zip` from an allow-list of tracked files, adds third-party notices, and refuses an archive holding `node_modules`, `.env`, workspace data, Git history, logs, credentials or personal paths. `--verify` and `scripts/clean-extract-test.{sh,ps1}` run the clean-extraction test. `forge upgrade --from <old>` carries `.env`, the config and projects across. See `docs/packaging.md`.
- T10: the Cursor path. `forge task next|check|submit|abandon` hands out one contract at a time and refuses a submission that changed files outside `owns_files` (or inside `must_not_touch`) before the verify command runs. `CLAUDE.md`, `AGENTS.md` and `.cursor/rules/forge.mdc` are generated from the Project Manager role and the command rules. A pre-commit hook (installed by the git plugin, or `forge hooks install`) runs `forge scan --staged`. See `docs/cursor.md`.
- T09: the Claude Code guard hook (`src/hooks/guard.mjs`, in `.claude/settings.json` and every `forge run` worker): `.env` is never read or written, the runtime's files change only through forge, a production deploy needs B7, and a task worker may write only its contract's files. Credentials are redacted from the ledger, recordings and verify logs, and `forge scan` finds secrets in files. See `docs/security.md`.
- T08 (second part): the `form-function` plugin (a Vercel function that checks each submission on the server, rate limits it and forwards it to `FORM_WEBHOOK_URL`, plus a local endpoint and `form-mock`), the `spline` plugin (scene checks and copying a scene into the site), and `setProjectEnv` on the vercel plugin.
- T08 (first part): the `git` plugin (a local repository per project), `local-preview` (serves a built site on 127.0.0.1) and `vercel` (preview deploys with B5, production with B5 and B7, through the REST API), each with a mock. See `docs/plugins.md`.
- T07: plugin host. Plugins are found in `plugins/` and `src/plugins/`, checked against the manifest schema, handed out by `getPlugin` only when enabled and fully configured, and each action is checked against the manifest's permissions and the project's approvals, then logged as `plugin_call`. Network access is limited to declared hosts, mock mode loads `mock.mjs`, and `forge plugins [list|enable|disable|check]` and `forge doctor` run health checks. See `docs/plugins.md`.
- T15: the Project Manager intake workflow. `runIntake` and `forge intake` ask, record answers and assumptions, and write `intake/brief.json`, `facts.json`, `estimate.json` and `plan.md`, stopping before B1. `estimateScope` with operator rates in `registry/estimate.json` and the new `estimate` schema. Client material can be read into facts by the model through a runner task.
- T14: the question bank (core questions plus goals, audience, pages and forms for each of the 7 project types), `selectQuestions` with scoring, rounds and follow-up rules, `recordAnswer`, `draftBrief`, `validateBrief`, `loadQuestionBank` and `loadRegistry`, with the A5 intake tests for the 7 sample briefs. See `docs/intake.md`.
- T16: the eight approach registry entries, the selection matrix, the condition evaluator, `loadApproaches` and `selectApproaches`, with 48 decision briefs (3 qualifying and 3 not, per approach) and `forge select`. See `docs/registry.md`.
- Task contracts can no longer claim the runtime's own files in `owns_files` (`project.json`, `ledger.jsonl`, `board/`, `locks/`), or a pattern that starts with a wildcard at the project root.
- T05: the 8 agent roles in `agents/<role>.md`, `forge agents generate` and `forge agents check` for the Claude Code subagents and Cursor rules, and phase routing: `forge run` starts only the tasks whose agent works in the current phase, and each worker gets its role instructions.
- T06: Claude Code worker adapter. Each task runs as a headless `claude -p` session with read and edit tools, its reply's evidence line is parsed, and failures map to typed errors (sign-in, rate limit, missing binary). Every attempt is recorded with the files it changed, and the replay worker plays recordings back identically, including failed attempts. `forge run [--replay <dir>]`.
- M1 interface freeze: open questions decided and recorded in `docs/interfaces.md`. The task board moves from `tasks/` to `board/`, verify logs move to `evidence/tasks/`, and `project.json` gains optional registry, question bank and schema versions.
- T03: project state machine (P0 to P15) with atomic `project.json` saves, an append-only ledger with torn-line repair, and approval enforcement: B1, B2, B3, B6 and B7 gate phase exits, and `requireApproval` refuses and records any action without its approval. `forge new`, `forge approve` and `forge status`.
- T04: task board and runner: dependency-ordered queue with a concurrency limit, per-file locks, a run lock per project, per-attempt timeouts, heartbeats, up to two retries before `blocked`, and `forge resume`, which requeues tasks with a stale heartbeat, discards their uncommitted changes and re-verifies submitted work without re-running the worker.
- T01: CLI skeleton with `--help`, `--version`, `doctor` and `validate`; launchers for macOS/Linux and Windows; config loader with safe defaults; setup scripts.
- T02: runtime schemas for the task contract, plugin manifest, gate result, ledger entry and config, with valid and invalid fixtures and tests.
- T13: project schemas for the brief, facts, question bank, approach registry, selection matrix, approach decision, design decision and rule condition, with valid and invalid fixtures, 7 sample briefs (one per project type) and tests. Project-side function signatures added to `docs/interfaces.md`.
